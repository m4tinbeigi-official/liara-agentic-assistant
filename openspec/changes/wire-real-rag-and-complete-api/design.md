## Context

حسابرسی e2e (۹/۹ سبز پس از رفع باگ‌های استاتیک‌سازی فرانت‌اند، قفل وابستگی‌ها و بلاک شدن event loop) ثابت کرد اسکلت عامل — مسیردهی intent، تولید کانفیگ، SSE و UI استریم — سالم است. شکاف واقعی در «زیرساخت دانش» و «سطح API وعده‌داده‌شده» است. این تغییر عمداً کوچک و جراحی طراحی شده: هیچ بازنویسی معماری انجام نمی‌شود؛ فقط حلقه RAG بسته و قراردادهای اعلام‌شده محقق می‌شوند.

## Goals / Non-Goals

**Goals**
- بستن چرخه کامل Ingest → Index → Retrieve → Cite بدون وابستگی به سرویس خارجی جدید.
- پاسخ به این سوال قابل اندازه‌گیری: «آیا برای N کوئری طلایی، سند مرجع صحیح داخل Top-3 بازیابی می‌شود؟»
- حفظ ۱۰۰٪ سازگاری رفتار فعلی API برای کلاینت‌های موجود (chat/health).

**Non-Goals**
- اتصال به LLM ابری یا افزودن کلید API (محدودیت نسخه بدون‌کلید حفظ می‌شود).
- پیاده‌سازی عملیات نوشتن روی لیارا (Deploy واقعی از داخل چت) — نیازمند تصمیم امنیتی جداگانه.
- مهاجرت از Qdrant یا تغییر ADR-003.

## Decisions

### D1. fastembed به جای sentence-transformers
`all-MiniLM-L6-v2` از طریق ONNX Runtime اجرا می‌شود؛ همان مدل، همان بعد برداری (۳۸۴)، بدون کشیدن torch (~۲GB). خروجی `ingest.py` و `search_docs` باید بیت‌به‌بیت نزدیک نباشد اما Recall روی مجموعه طلایی باید برابر یا بهتر شود (تست مقایسه‌ای در tasks).

### D2. BM25 در حافظه با rank_bm25 + توکنایز چندزبانه
برای مقیاس مستندات لیارا (~چند هزار چانک) ایندکس BM25 در RAM کافی و بی‌نیاز از سرویس جانبی است. توکنایزر: جداسازی کلمه یونیکد + lowercase + حذف نویسه‌های کنترلی؛ زبان فارسی نیازمند stemmer سنگین نیست چون کوئری‌ها عمدتاً شامل نام پکیج/فلگ انگلیسی‌اند (مبنای ADR-001).

### D3. ادغام نتایج با Reciprocal Rank Fusion (k=60)
هر دو retriever Top-20 می‌دهند؛ RRF بدون نیاز به کالیبراسیون امتیاز، پایدارتر از وزن‌دهی خطی است.

### D4. ساختار خروجی retrieval
`search_docs(query, top_k)` به‌جای رشته، لیستی از `{"text", "url", "section", "platform", "score"}` برمی‌گرداند. `agent.py` مسئول قالب‌بندی Markdown + بخش «منابع» است. fallback فعلی فقط زمانی فعال می‌شود که نتیجه معتبر صفر باشد — نه هر بار.

### D5. ایندکس‌سازی آفلاین و Idempotent
`python ingest.py --source git|dir` با قفل فایل اجرا می‌شود؛ در startup سرور اگر کالکشن خالی بود فقط هشدار می‌دهد (نه rebuild خودکار — جلوگیری از timeout اولین request و فشار به GitHub در restart های مکرر PaaS).

### D6. قرارداد خطای یکنواخت API
خطاها همیشه `{"error": {"code", "message_fa"}}` با status مناسب (422 اعتبارسنجی، 503 وابستگی خارجی). Pydantic مدل‌های ورودی برای هر سه اندپوینت جدید اجباری است.

## Risks / Trade-offs

- **کیفیت چانک‌بندی MDX:** فرانت‌مترها و کامپوننت‌های embed شده می‌توانند متن را بشکنند → پاک‌سازی regex + آزمایش دستی روی ۱۰ فایل نمونه پیش از ایندکس کامل.
- **سرد بودن دیسک روی Liara:** اولین جست‌وجو پس از deploy مدل ONNX را load می‌کند (~۱-۲s) → prewarm در lifespan سرور.
- **نرخ محدودیت GitHub:** clone کامل یک بار و نگهداری در دیسک دائمی؛ sync دوره‌ای اختیاری با `--incremental`.

## Migration Plan

1. merge ماژول‌های جدید با flag محیطی `RAG_ENABLED=0` (پیش‌فرض رفتار فعلی).
2. ingest دستی روی محیط dev → اجرای تست Recall → فعال‌سازی `RAG_ENABLED=1`.
3. Deploy لیارا با دیسک دائمی موجود (`vector-db-data`)؛ اجرای `ingest.py` به‌صورت one-off.
